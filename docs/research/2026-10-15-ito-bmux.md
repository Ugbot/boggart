# Ito ideas for Boggart and BMUX

Research refreshed: 2026-10-15. Recommendation: borrow selected Lua UI patterns;
keep Boggart's native terminal, execution owners, common Fleet and C/Lua runtime.
Ito is useful for making controls consistent and large transcripts cheaper. It
does not supply the agent/worktree control plane BMUX is building.

## Evidence and scope

Read the requested [playground](https://uji.sh/ito/) and its linked
[API guide](https://uji.sh/ito/ito.md), then inspected public upstream source:

- **Ito:** `08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f`, 2026-10-14;
  package version 0.1.5. A declarative Lua TUI library inspired by SwiftUI.
  Its native implementation uses Rust/mlua, Ratatui, Crossterm and Tokio;
  the browser demonstrates the same Lua layout/state/input through WASM and
  Canvas. It is not a shell, terminal emulator or multiplexer.
  [README](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/README.md),
  [dependencies](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/Cargo.toml),
  [browser scope](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/web/README.md).
- **Companion uji:** initially `9a612f15a772921867f8df688e1630f2ae6aa834`, version
  0.2.3. A separate coding harness using Ito. Its replaceable screens,
  session API, modal stack and subagent plugin belong to uji, not Ito.
  [README](https://github.com/uji-labs/uji/blob/9a612f15a772921867f8df688e1630f2ae6aa834/README.md),
  [UI API](https://github.com/uji-labs/uji/blob/9a612f15a772921867f8df688e1630f2ae6aa834/docs/src/api/ui.md),

## Ranked remaining recommendations

### 1. Adapt host-supplied text metrics; avoid Ito's editor/width fallback

**Design inspiration, not a Unicode implementation to copy.** Ito permits the
host to inject display width; its browser supplies Rust `UnicodeWidthStr`.
However, default Lua width counts code points, `clip`/long-word wrapping iterate
UTF-8 scalars, and `Line` movement/backspace advance over scalar boundaries.
These are insufficient evidence for whole-grapheme editing/truncation of ZWJ
emoji, modifiers, flags, combining sequences or Indic conjuncts. Browser
Canvas/font fallback also does not establish SDL shaping/color-emoji parity.
[host](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/host.lua),
[text](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/text.lua),
[editor](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/line.lua),
[WASM host](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/web/src/main.rs).

**Boggart seam:** native terminal/grid shaping, grapheme composer editing and
color-glyph code/tests already exist. This research does not certify all their
platform/font combinations. The actionable gap is consistent consumers:
`SwarmView` still pairs `dash.clip` with generic `renderer.draw_text`;
[dash](../../lua/dash.lua) uses scalar `sys.width/wtake`, and
[tui/agents](../../lua/tui/agents.lua) still measures/truncates by code point.
Migrate each SDL consumer's measurement, prefix, wrapping and painting together
to existing `sys.cell_width/cell_take` and grid drawing, keeping its unit/width
policy explicit. Choose the external-terminal policy before changing cTUI
metrics; terminal grapheme mode is not universally negotiated.

**Ticket:** remaining BMUX-19/25 work; add common-Fleet coverage to BMUX-43.
Acceptance: names, cwd, task text, action labels and history use matching measured
and painted widths; never cut inside `é`, `👩‍💻`, `👍🏽`, `🇬🇧`, `❤️` or `क्ष`;
check selection/copy, narrow widths and fallback/color fonts in actual SDL.
Reuse Boggart's native APIs and corpus, not Ito's scalar editor. See existing
[layout contract](../terminal-text-layout.md),
[grapheme edit test](../../tests/studio_grapheme_edit.lua), and
[color emoji test](../../tests/studio_color_emoji.lua). Some layout prose still
says color emoji is unsupported; current implementation/tests have moved ahead
of that statement, so it is not used as evidence of a remaining absence here.

### 2. Add anchored, lazy scrolling to Fleet detail and long agent transcripts

**Borrow next.** Ito's `LazyVStack` builds/measures the visible variable-height
items, caches heights by width/revision, and stores the top visible item's stable
ID plus subrow/offset. New output follows the end only while follow mode is active;
scrolling up holds the reading position. It sweeps unused composition nodes.
Tests cover append while scrolled up, end/top jumps and unchanged rows.
It is not a blanket O(visible) guarantee: identity lookup can scan the list and
`content_height` intentionally measures all rows.
[implementation](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/controls/lazy_vstack.lua),
[tests](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/tests/views_spec.lua).

**Boggart seam:** Fleet detail/journal currently display a tail, and the wheel
moves roster selection. Give detail its own scroll target and anchor
`(agent_id, generation, entry_id, subrow, offset)`; offer Jump to latest.
[AgentView](../../studio/data/core/agentview.lua) already caches wrapped entry
layout and handles append-only streaming, so improve its item-height/index and
anchor handling rather than replacing its parser or wrapping. Keep native BMUX
scrollback and [TerminalView](../../studio/data/core/terminalview.lua) outside this
change: C already owns visible/damaged rows and capture caches.

**Ticket:** separate Fleet detail/history usability follow-up, reusable in
BMUX-43; use BMUX-27 only for the distinct native terminal scrollback surface.
Acceptance: appending output cannot move a scrolled-up reader; resizing retains
the same logical entry; collapsed tool output preserves a sensible anchor;
evicted history falls back predictably; a long-history benchmark counts layout
calls and allocations as well as frame time. Avoid materializing all wrapped
history merely to compute a scrollbar.

### 3. Share a small presentation model, not another execution registry

**Borrow selectively.** Ito separates Lua view/state/input from a native
`Surface`; real terminal, virtual test terminal and Canvas use that boundary.
The same example Lua views are exercised through the terminal test host.
That is a useful parity discipline, not evidence that Canvas improves desktop
performance.
[surface](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/src/tty/surface.rs),
[virtual backend](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/src/tty/virtual_screen.rs),
[parity tests](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/tests/browser_parity_spec.lua).

**Boggart seam:** keep [fleet.lua](../../lua/fleet.lua) as the common registry and
[fleetagents.lua](../../studio/data/core/fleetagents.lua) as its Studio adapter.
Extend the existing action extraction with a pure Lua projection, tentatively
`lua/fleetview.lua`, for labels,
attention/unknown-activity wording, ordered detail fields and action descriptors.
Have SDL Fleet and, as its shared-roster access is implemented, the cTUI consume
that projection. Build on existing pure styled-run contracts in
[termrender](../../lua/termrender.lua) and [tui/agents](../../lua/tui/agents.lua).
Share semantics and fixtures; allow the renderers different layouts.

**Ticket:** attach to BMUX-43 and the BMUX-35 cTUI work. Acceptance: one fixture
for native workers, launched TUIs and foreign hook-only agents yields consistent
status/actions on each surface. A virtual view harness should validate focus and
actions, supplemented by the existing real SDL/PTY tests. This advances surface
parity; server-owned terminal execution already exists, while attaching the
Studio/cTUI surfaces remains BMUX-72/32/34 work.

### 4. Use explicit revisions and animation deadlines to reduce idle UI work

**Measure before adopting.** Ito tracks which state/observable fields each view
reads, invalidates dependents on changed values, and memoizes composition. Its
frame collects the earliest requested animation wake. In-place mutation of a
nested plain table does not notify it; this caveat is documented and visible in
the implementation.
[state](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/runtime/state.lua),
[observable](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/runtime/observable.lua),
[composition](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/runtime/composition.lua),
[wake](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/lua/ito/frame.lua).

**Boggart seam:** introduce explicit per-record/roster presentation revisions in
`fleet.lua` and cache projection/layout in `SwarmView` against revision, width
and theme. Preserve process/lease polling independently; provider events do not
replace liveness checks. Schedule elapsed-time labels/spinners at their next
visible deadline. Avoid wrapping the mutable registry in metatable observables
or adding an entire reactive composition runtime for this purpose.

**Ticket:** measurements in BMUX-10/28, with BMUX-40 as the later event source.
Acceptance: benchmark 1/10/100 idle panes, Fleet hidden/visible and a terminal
flood; record CPU, allocations and input-to-paint latency. Do not promise an
improvement until measured. Native terminal row/atlas optimization remains its
existing workstream.

## Licensing and things to avoid

- **Ito is MIT:** its pinned LICENSE was re-read. Code reuse is possible with its copyright/license notice in
  copied or substantial derived portions. Any port should be narrow, pinned and
  attributed. **uji is GPL-3.0-or-later:** keep its harness/screens/plugins as
  design references; do not copy them into Boggart's current BSL code without a
  separate licensing decision. The refreshed uji HEAD retains the same
  GPL-3.0-or-later declaration and GPL LICENSE. These are different repositories/licenses.
  [Ito license](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/LICENSE),
  [uji license declaration](https://github.com/uji-labs/uji/blob/9a612f15a772921867f8df688e1630f2ae6aa834/README.md#license),
  [Boggart license](../../LICENSE).
- **Do not replace the renderer or import the stack wholesale.** Ito's Rust
  host adds mlua/Ratatui/Tokio and a second terminal abstraction; the playground
  adds a browser loader and whole-frame Canvas snapshots. No new Python or JS
  application runtime is needed to reuse the ideas. A future preview gallery
  could use native Lua/SDL fixtures, after the actual controls work.
- **Do not treat the playground as a remote-agent protocol.** Its bounds,
  instruction budget, no-filesystem browser host and full frame snapshots solve
  an interactive demo problem. They do not supply durable PTYs, reconnect/event
  cursors, worktree ownership or foreign-provider semantic controls.
  [browser scope](https://github.com/uji-labs/ito/blob/08c6a5ac8bdf72f3595db17cf2c32a10edca3f9f/web/README.md).
- **Do not simplify all decisions to yes/no.** uji's documented confirmation API
  is a convenient modal interface, not a replacement for Boggart's exact provider
  request/option IDs and capability checks. Its subagent plugin starts separate
  uji processes and returns final answers; Boggart already has scheduler workers,
  supervision and shared Fleet. Copying that model would duplicate ownership.
  [confirmation API](https://github.com/uji-labs/uji/blob/9a612f15a772921867f8df688e1630f2ae6aa834/docs/src/api/ui.md#ujiuiconfirmopts-on_done),
  [subagent model](https://github.com/uji-labs/uji/blob/9a612f15a772921867f8df688e1630f2ae6aa834/docs/src/plugins/subagent.md).

**Actual reuse decision:** no upstream component is recommended for verbatim
adoption now. `LazyVStack` is MIT but depends on Ito's View/composition/frame
runtime; port its anchor/measurement strategy into existing Boggart views. A
future narrow code port needs a pinned diff and attribution. Focus and
presentation ideas can be independently implemented in ordinary Lua, with C11+
and SDL3 retaining terminal, text and transport ownership.

Keep structured foreign adapters, tracker/worktree assignment and thin attached
clients on the existing roadmap. Finish common-Fleet Unicode consistency, then
anchored history; the previous keyboard recommendation is complete. No new
tracker tickets or product changes were made by this research.
