# BMUX-15/16: terminal storage and dispatch

**Goal:** Connect the verified C parser to a C screen and expose a headless
terminal object, then integrate it with the PTY and renderer in subsequent work.

**Architecture:** `lstyle` interns tagged colours/attributes with owned style
references. `lpage` owns fixed-size row pages, a visible row ring, a bounded
history ring and row damage. `bterm` owns primary/alternate screens, cursor,
modes, SGR pen and reply sink; parser events call grid operations directly.
`lterminal` exposes this core to both Lua front ends and the benchmark harness.

**Constraints:** One mutable instance per terminal, no process-global state;
no Lua calls on the byte path; no shifting scrollback on full-screen scroll;
retain styles before releasing overwritten cells. Keep source attribution and
the C99 build. Wide/grapheme/reflow correctness has BMUX-19/20 gates. Product
PTY integration remains BMUX-21; BMUX-16's app-rendering criterion must be
verified against real applications rather than inferred from unit tests.
