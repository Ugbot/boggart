# Common invocation admission

`invoke.call(context, capability_id, args, options?)` returns a value or
`nil, {code, message, retryable}`. Successful structured values are preserved.
`invoke.string` is the compatibility adapter used by `tools.run`, `tools.call`
and `tools.get`: legacy tools retain their string output and shaped tool errors.
Generated composition, fallback targets, CLI permission wrappers, child agents
and Studio's custom runner all enter this gate.

A trusted host creates an opaque `invoke.context` handle:

```lua
local context = require('invoke').context {
  state = permission_state,
  policy = compiled_policy,
  ledger = shared_quota_ledger,
  approve = function(name, args, why) return explicit_user_approval end,
}
local result, err = require('invoke').call(context, 'read', {path='/project/input'})
```

The optional second `context` argument is an ancestor handle; otherwise the
current coroutine context is inherited. `allow` is an additional tool allowlist.
`invoke.with_context(handle, fn, ...)` installs a context for protected host
execution; `invoke.current()` returns its opaque handle. Generated code receives
none of these host APIs. Generated coroutines and event observation coroutines
inherit the current authority. Every generated `resume`, `wrap` call and `close`
intersects creation authority with the current caller and retains restrictions
acquired by previous resumptions, including across suspended gate cleanup.
Saved-coroutine hooks compose creation and resumer limits in a flat plan that
deduplicates hook identities; repeated ordinary yields do not reset counters. Every nested call intersects the supplied and
active contexts. Cleanup restores the previous coroutine context after errors.

Legacy state is snapshotted and current host state is checked again for
revocations. Live global permission state also applies to surface-local state.
Later grants cannot remove a pinned restriction. A change to a pinned generic
policy requires a fresh host context (`policy_changed`); this conservatively
stops the old run rather than retaining revoked quota or resource authority.
Legacy headless approval behavior remains governed by `perm.headless_decision`.
Generic mandatory approvals require an explicit callback result of `true`;
legacy implicit headless allowance does not satisfy them.

Trusted registries bind once per generation using
`invoke.bind(owner, resolver, runner, format_result?)`. The optional formatter is used only by the legacy string adapter, inside the
invocation boundary; raw `invoke.call` keeps structured values and syscall
packed return tables unchanged. A resolver returns host metadata
`{id, version, effect, resources?}`; a runner receives `(id, args)`.
`options.registry` selects a host registry owner; default dispatch resolves the
published tools module. Candidate tools modules have separate bindings, so a
failed reload cannot replace the live registry's private dispatcher. Neither
raw dispatch nor registration is available in generated environments.
`options.runner` is a trusted compatibility hook for custom host runners.

Tool descriptors use the registered name as identity; callers cannot supply
resource labels. Built-in filesystem adapters resolve paths using native
`uv.fs_realpath`, resolving the existing parent for a newly created file.
A missing/unresolvable resource refuses resource-constrained admission.
Trusted custom descriptors can supply their own resource extractor. This is
application admission, not protection against filesystem races or privileged
in-process Lua/native code.

Inherited quota scopes are deduplicated and reserved together in one ledger
transaction. Conflicting versions of one scope or multiple ledger authorities
are refused before debit. IDs are generated by the host; caller arguments do
not choose them. A replayed reservation never dispatches. Settlement failure
quarantines that ledger object until host recovery; ledger overrun also retains
its durable quota halt. Call quotas are supported. Current legacy runners have
no provider cost-ceiling contract: token, monetary and other non-call limits or
quota metrics return `unsupported_limit` before dispatch. Estimates alone do
not authorize unbounded spending; bounded provider adapters belong to BRAIN-17.

Every attempted invocation emits `tool:before` and one `tool:after`, including
unknown tools, denials and runner errors. They share `invocation_id`; terminal
data includes error code, result byte count and evaluated policy revisions.
Observation arguments are copies. After a yielding approval, live policy and
resource identities are rechecked immediately before reservation/dispatch. A
changed registry entry/runner is refused with `capability_changed`. Authorization uses the distinct
`tool:authorize` query: any veto denies, and throwing or over-budget authorizers
fail closed. **Migration:** veto handlers formerly registered on `tool:before`
must move to `tool:authorize`; `tool:before` is now observation only. Ordinary
observers need no changes. Terminal observers retain the invocation's authority;
a failed invocation cannot start new effects from terminal callbacks.

Generated environments expose copied standard-library tables and hide built-in
metatables. `sys` compatibility functions enter individually named capabilities
(`sys.read`, `sys.write`, `sys.exec`, etc.), with legacy write/bash guards applied
to their effectful aliases. `gold.re` remains available as pure helpers;
`gold.fs.read`, `write` and `glob` use the mediated facade. `tools.names` enters
`registry.names`, so registry enumeration can be denied separately. `db`, `data`
and other `gold` features are deliberately unavailable pending explicit
capability adapters. Trusted installed modules remain privileged. Lua hooks and
these facades are not an OS sandbox.

Regression coverage lives in `tests/invoke.lua`, with Studio integration in
`tests/studio.lua` and enclosing-hook checks in `tests/luatool.lua`.
